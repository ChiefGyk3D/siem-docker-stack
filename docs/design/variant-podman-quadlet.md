# Design: Podman variant, rootless Quadlet units managed from Cockpit

Status: DRAFT for the owner's decision. Docs only: no code, no configuration, no
live change. Issue #112, child of the deployment variants epic #111, under epic
#62. Sibling design: [variant-compose-baseline.md](variant-compose-baseline.md).
Builds on [podman.md](podman.md), which this document does not repeat: read its
sections 3 and 4 for the rootless limits (no macvlan, no ports below 1024 without
the privileged-port sysctl, volume ownership, cadvisor and Portainer rework).

Marking. **VERIFIED** names a repo file at origin/master 7c8de1b or a vendor URL
with the date read (all vendor pages read 2026-11-19; a page read in part says
so). **INFERRED** is reasoning not checked against a source or a running host;
every INFERRED item is a rehearsal-host test. Examples use `example.com` and
placeholders only; no value of any setting appears here.

Searches run for items not found on a vendor page:
`query: cockpit-podman manage quadlet containers rootless user session`;
`query: loginctl enable-linger rootless podman systemd user services start at boot without login`.

## 1. Goals and non-goals

Goals (issue #112 done-when: one documented path brings the stack up rootless and
it survives a reboot):

1. One non-root service account runs every stack container as systemd user
   units generated by Quadlet.
2. The stack starts at boot with nobody logged in, and the units are visible,
   startable and stoppable from Cockpit.
3. The host-specific values live in one file (section 4), the same file the
   Compose baseline uses, so the two variants do not drift.
4. Hardening is declared per unit and is reviewable as text.

Non-goals:

- Not a replacement for the Compose baseline. Docker Compose stays the default
  (podman.md section 1, owner decision pending there as Q10).
- Not a Kubernetes path (`.kube` units) and not a pod per tier in the first
  release (section 3 explains why).
- Not auto-update by default. The repo's pin-every-dependency policy and the
  seven-day hold apply (section 7).
- Not the n8n router. It is outside the compose file today and is optional
  (optional-components.md). The macvlan constraint in podman.md section 3.6
  still means a rootless n8n has no LAN address of its own.
- Not a converter tool. A generator such as podlet would be a new tool and needs
  an ai-hardening record before use (podman.md section 3.5, owner rule).

the rootless column and answers each podman.md blocker with a decision to take:

## 3. Unit layout

Quadlet reads these file types from a search path and generates units
(VERIFIED, https://docs.podman.io/en/latest/markdown/podman-systemd.unit.5.html,
2026-11-19, first 100000 of 105724 characters): `.container`, `.network`,
`.volume`, `.pod`, `.kube`, `.image`. Rootless search paths on that page:
`$XDG_RUNTIME_DIR/containers/systemd/`, `~/.config/containers/systemd/`,
`/etc/containers/systemd/users/${UID}` and `/etc/containers/systemd/users/`.
Subdirectories are searched recursively. Rootless Quadlets cannot use the
systemd `User`, `Group` or `DynamicUser` options; the service account is created
instead.

Recommended layout (a proposal, nothing exists yet):

```
/etc/containers/systemd/users/<uid>/siem/      # admin-owned, root:root 0644
  siem.network                                 # replaces the siem-net bridge
  opensearch-hot.container   opensearch-warm.container
  opensearch-dashboards.container   logstash.container
  grafana.container   influxdb.container
  prometheus.container   prometheus-otlp.container   alertmanager.container
  elasticsearch-exporter.container
  wazuh-manager.container   wazuh-indexer.container   wazuh-dashboard.container
  syslog-ng.container   unifi-poller.container
  optional/crowdsec.container                  # only when enabled
  siem.target                                  # plain systemd unit, groups the stack
~/.config/siem/siem.conf                       # the one host-specific file (section 4)
```

Why the `/etc/containers/systemd/users/<uid>/` path (INFERRED choice, the path is
VERIFIED): the files are owned by the administrator, not by the service account,
so a compromised stack cannot rewrite its own unit files. The files in `users/`
(no uid) would run for every user's login session, which is wrong for a shared
host (VERIFIED on the page).

Design rules:

1. One `.container` file per compose service, same `ContainerName=` as the
   compose `container_name` (VERIFIED the compose names are scripts' contract,
   podman.md section 3.1). INFERRED: `ContainerName=` exists; the key list read
   here did not print it, check it in the first rehearsal.
2. One `.network` unit named after `siem-net`. A `Network=siem.network` line
   makes each container depend on it (VERIFIED, podman.md section 3.5 from the
   same page). The fixed OpenSearch addresses (172.20.0.10 and .11, VERIFIED
   compose) are used only by compose; clients use names (VERIFIED podman.md
   section 3.6), so the Quadlet network may use a different subnet that the
   config file names.
3. No `.pod` in the first release. A pod shares one network namespace; the stack
   has 18 services (VERIFIED compose, two behind profiles) with different bind addresses and different reload needs, and
   one unit per container keeps Cockpit's start and stop per service. INFERRED;
   revisit if per-tier start-up ordering needs it.
4. A `siem.target` groups all units with `WantedBy=` so `systemctl --user start
   siem.target` starts the stack and one `disable` removes it. A plain systemd
   target unit; Quadlet passes `[Install]` and `[Service]` keys through
   (VERIFIED, podman.md section 3.5).
5. Restart policy: `Restart=always` in `[Service]` replaces `restart:
   unless-stopped` (VERIFIED the compose uses `unless-stopped` on every service).
   The semantics differ: `unless-stopped` stays stopped after a manual stop
   across a daemon restart; a systemd unit stopped by hand stays stopped until
   the next boot or an explicit start (INFERRED). Document it.
6. Ordering replaces `depends_on`. Quadlet translates `Requires=`, `After=` and
   related keys between Quadlet units (VERIFIED, same page). Five services wait
   on `opensearch-hot` being healthy today (VERIFIED compose lines 176 to 190 and
   others). The page documents `Notify=healthy`, which postpones the start
   notification until the container is healthy and requires a healthcheck such as
   `HealthCmd=` (VERIFIED). So those five units use `After=` and `Requires=` on
   the `opensearch-hot` unit with that unit set to `Notify=healthy`. INFERRED that
   a dependent start then waits correctly; test by starting the dependents first.
7. Images are named fully qualified in every unit (VERIFIED requirement for
   `AutoUpdate=registry`, same page; podman.md section 6 INFERRED short names can
   fail non-interactively). Pins come from the config file's version variables.
8. Healthchecks: `HealthCmd=` per unit. Only two services have a healthcheck
   today (VERIFIED compose lines 93 and 144, both OpenSearch, using `curl`).
   Others need a new check that uses a tool the image contains (section 6).

Rootless boot start. A user service must be allowed to run without a login:
`loginctl enable-linger <account>` and an `[Install]` target such as
`WantedBy=default.target` (search result summaries, vendor pages from Red Hat
and Oracle listed in the search, not fetched in full; INFERRED as the required
step). One secondary result claims linger is no longer necessary on current
Podman; not confirmed from the man page, so the done-when test (section 9) must
include a real reboot with no login, not just `systemctl --user` after login.

## 4. The single host-specific config file (names only)

Same contract as the Compose baseline: one file, `siem.conf` in the account's
config directory for this variant, with the same variable names as `.env`
(VERIFIED the 99 names in `.env.example` and the compose interpolation).
Quadlet units read it through `EnvironmentFile=` in `[Service]` (the systemd
page, VERIFIED in secrets-sources.md: path must be absolute, UTF-8, a missing
file stops the service unless prefixed with `-`).

Important Quadlet limit (INFERRED, not read): `EnvironmentFile=` fills the
environment of the unit's `ExecStart`, and the container only sees variables
passed with `Environment=` or `EnvironmentFile=` keys of the `[Container]`
section, or `--env-file` through `PodmanArgs=`. The first rehearsal must prove
which key delivers a value into the container. Values for `Image=` and
`PublishPort=` lines are also expanded by Quadlet or systemd, with different
rules (INFERRED); to avoid that ambiguity, the config file feeds a small render
step (implementation issue) that writes the final unit files, as the repo already
does for Alertmanager (`scripts/render-alertmanager-config.sh`, VERIFIED to
exist). Open question Q2.

Names the file must carry (the groups, drawn from `.env.example`):

- Placement: `BIND_ADDR`, `INGEST_BIND_ADDR`, `SIEM_HOST`, `SIEM_USER`,
  `TZ`, `SIEM_ALLOWED_CIDR`. New for this variant (names only, proposed):
  `SIEM_DATA_HOT`, `SIEM_DATA_WARM`, `SIEM_NET_SUBNET`.
- Ports: the existing `*_PORT` variables (`OPENSEARCH_PORT`,
  `OPENSEARCH_DASHBOARDS_PORT`, `GRAFANA_PORT`, `INFLUXDB_PORT`,
  `PROMETHEUS_PORT`, `ALERTMANAGER_PORT`, `WAZUH_*_PORT`, `SYSLOG_UDP_PORT`,
  `SYSLOG_TCP_PORT`, `LOGSTASH_*_PORT`, `PROMETHEUS_OTLP_PORT`).
- Sizing: `OPENSEARCH_HOT_HEAP`, `OPENSEARCH_WARM_HEAP`, `LOGSTASH_HEAP`,
  `WAZUH_INDEXER_HEAP`, `PROMETHEUS_OTLP_MEM_LIMIT`, retention variables.
- Image pins: the `*_VERSION` variables.
- Secret names (values never in this file when a secret source is used; see
  section 8): every `*_PASSWORD`, `*_SECRET`, the Matrix and SMTP names.

VERIFIED gap: the compose file hard-codes `/data/hot` and `/data/warm` in 20
places, the subnet 172.20.0.0/24 and fixed addresses, and the loopback host ports
9300, 9600, 9301 and the 1515 and 9443 mappings (grep of docker/docker-compose.yml,
2026-11-19). None is a variable. The Compose baseline design proposes the
variables; this variant reuses them. Without that change, the Quadlet render step
would be the only place those values are configurable, which splits the contract.

Permissions: mode 600, owned by the service account, refused otherwise (the same
rule secrets-sources.md proposes for `.env`).

## 5. Rootless identity, ownership and limits

Facts (VERIFIED podman.md section 3.2 and 3.4; not repeated): subuid ranges give
65536 ids, host mounts need an ownership decision, `:U` changes owners and breaks
Docker rollback.

New decisions for the Quadlet form:

1. Dedicated account, no login shell, `/etc/subuid` and `/etc/subgid` ranges
   recorded by the administrator. INFERRED: `systemctl --machine account@ --user`
   is the supported way to drive a nologin user (VERIFIED on the unit page: "For a
   user with `/sbin/nologin`: `sudo systemctl --machine username@ --user
   list-unit-files`").
2. Ownership table. The compose `user:` lines are 472 (grafana), 65534
   (prometheus, prometheus-otlp, alertmanager) and OpenSearch is uid 1000
   (VERIFIED compose and scripts/07-generate-opensearch-certs.sh via podman.md).
   Under rootless, host-visible owners are subuid offsets. Use `UserNS=` per unit
   (VERIFIED the key exists, form `MODE[:OPTIONS,...]`); `keep-id` with `uid` and
   `gid` options is INFERRED, not read on the page excerpt. The design requires
   one table in the implementation doc: container uid, host owner, directory.
3. Fresh install first. The owner's migration from the docker host is a data
   move; a copy with `podman unshare chown` is run once per directory with the
   original owner recorded (podman.md section 7 rollback rule).
4. Limits. `LimitMEMLOCK` and `LimitNOFILE` in a user unit "can only be lowered
   or the soft limit raised up to the hard limit" (VERIFIED systemd.exec page,
   2026-11-19). The compose file asks for memlock unlimited and nofile 65536 on
   both OpenSearch nodes (VERIFIED lines 60 to 66). So the account's user manager
   needs a hard limit set by the administrator (a `user@.service` drop-in or PAM
   limit), then `Ulimit=` in the unit. INFERRED; if it cannot be done, set
   `bootstrap.memory_lock=false` and accept swapping risk (decision D4).
5. `vm.max_map_count` stays a host sysctl set by `scripts/02-bootstrap.sh`
   (VERIFIED in podman.md section 4). A rootless container cannot set it; that is
   an administrator step, listed in section 11.

## 6. Security hardening

Two layers: systemd sandboxing of the unit that wraps `podman run`, and
container-level options in the `[Container]` section. Quadlet-supported
container keys are VERIFIED on the unit page (2026-11-19): `ReadOnly=`,
`ReadOnlyTmpfs=` (default true, tmpfs on /dev, /dev/shm, /run, /tmp, /var/tmp
when the root is read-only), `NoNewPrivileges=`, `DropCapability=`,
`AddCapability=`, `SecurityLabel*=`, `UserNS=`, `SubUIDMap=`, `Ulimit=`,
`Memory=`, `PidsLimit=`, `Sysctl=`, `HealthCmd=`, `HealthOnFailure=`, `Notify=`,
`Secret=`, `AutoUpdate=`, `Pull=`.

### 6.1 systemd layer (user units)

VERIFIED (systemd.exec, 2026-11-19, first 100000 of 244969 characters):

- `NoNewPrivileges=`: no gain of privilege through setuid or file capabilities,
  applies to the unit's processes. No user-service restriction is stated.
- `ProtectSystem=`, `ProtectHome=`, `PrivateTmp=`, `CapabilityBoundingSet=`:
  the page says namespacing options are not available to user services except
  where `PrivateUsers=` is implicitly enabled and the kernel allows unprivileged
  user namespaces. `ProtectSystem=` is stated as requiring file system namespacing
  "not available to user services".
- `UMask=`: user units inherit the per-user manager's value.

Consequence (INFERRED): for a rootless stack most of the useful sandboxing is the
container itself plus the unprivileged account. The unit layer adds
`NoNewPrivileges=yes` and `UMask=0077`; the namespacing directives are tried on
the rehearsal host and kept only if the unit still starts. The rootful alternative
(podman.md Q1) allows the full sandbox set, at the cost of a root-owned runtime.
`RestrictAddressFamilies=` and `MemoryDenyWriteExecute=` were not in the part of
the page read; not claimed. `MemoryDenyWriteExecute` would in any case break
JVM and Go runtimes (INFERRED), so it is not a candidate for these images.

### 6.2 Container layer: what each image allows

The compose file sets none of `read_only`, `cap_drop`, `security_opt`,
`pids_limit`, `tmpfs` or `privileged` (VERIFIED, grep of docker/docker-compose.yml,
2026-11-19), and has healthchecks on only the two OpenSearch nodes. So every
entry below is a NEW constraint, and whether a given image tolerates it is
INFERRED until the rehearsal host proves it. Order of work: apply to one unit,
read its log, loosen only the single failing item and record why.

| Control (Quadlet key) | Applies to | Basis |
|---|---|---|
| `NoNewPrivileges=true` | all units | Safe default for services that do not need setuid helpers. INFERRED for each image; the Wazuh manager image runs an init that may use `su` (INFERRED, test) |
| `DropCapability=all` then `AddCapability=` only what fails | all units | Rootless already caps the capability set to the user namespace (INFERRED). Expected adds: none for Grafana, Prometheus, Alertmanager, exporters (INFERRED); `CHOWN`, `DAC_OVERRIDE`, `FOWNER`, `SETUID`, `SETGID` possible for images that start as root and drop privileges (Wazuh, syslog-ng, InfluxDB, INFERRED) |
| `ReadOnly=true` | grafana, prometheus x2, alertmanager, elasticsearch-exporter, unifi-poller, opensearch-dashboards | These write only to bind-mounted data or `/tmp` (INFERRED from the mounts: data paths are separate bind mounts, VERIFIED compose). `ReadOnlyTmpfs` default true covers /tmp (VERIFIED) |
| `ReadOnly=false` | OpenSearch x2, wazuh x3, logstash, influxdb, syslog-ng, crowdsec | Entry points write config or keystores into the image tree (INFERRED; Wazuh and OpenSearch images generate files at start). Revisit with tmpfs mounts per path after observing writes |
| `Memory=` per unit | all, from config names | Only one limit exists today: `mem_limit` on prometheus-otlp (VERIFIED line 369). Use a tool the image has: the existing `curl` check for OpenSearch; for the others, INFERRED that wget or the binary's own `--version` is not a health check. Prefer a TCP connect check or the service's own `/-/healthy` or `/api/health` URL with a tool present in the image. Unknown per image; list as work in the implementation issue |
| `UserNS=` | all | Section 5 |
| `SecurityLabelDisable` | none | Keep labels on; use `:z` volumes for files shared across containers (VERIFIED podman.md section 3.4: several certs are mounted into more than one container, so `:z` not `:Z`) |
| `Secret=` | later | Podman secrets as files; most images here read environment variables (VERIFIED secrets-sources.md Option C rejection) |

Units that need exceptions, recorded up front:

- `syslog-ng`: UDP and TCP 514. Under rootless networking the source address of
  UDP senders may be rewritten (INFERRED, podman.md section 4); detection depends
  on the real sender address, so measure before moving it.
- `cadvisor`: not carried (D5). `/var/lib/docker` does not exist on Podman
  (INFERRED, podman.md). If kept, it needs read access to `/`, `/sys` and other
  users' cgroups, which a rootless account lacks (INFERRED).
- `portainer`: not carried; it mounts the Docker socket read-write, which is root
  on a Docker host (VERIFIED compose comment, line 644).
- `crowdsec`: reads `/var/log` (VERIFIED line 631); a rootless user cannot read
  root:adm logs such as auth.log (INFERRED). The profile is not part of the first
  release.

Secrets in units: never in a `.container` file, `Environment=` or `SetCredential=`
(world-readable through unit files; VERIFIED https://systemd.io/CREDENTIALS/ per
secrets-sources.md, 2026-11-19). See section 8.

## 7. Update and rollback

Update (decision D6). Default: manual and pinned. The owner changes a
`*_VERSION` name in the config file, re-renders, then `systemctl --user restart`
for that unit. `AutoUpdate=` is available (VERIFIED: `registry` needs a fully
qualified image, `local` restarts the unit when the local image changed), and
Podman's own timer is `podman-auto-update.timer`, firing daily at midnight
(VERIFIED, https://docs.podman.io/en/latest/markdown/podman-auto-update.1.html,
2026-11-19). It is NOT recommended here: the stack pins versions and holds a new
release seven days (owner rule), and an unattended daily pull defeats both.
Several images still default to `latest` (VERIFIED compose: grafana, prometheus,
syslog-ng, unifi-poller, crowdsec; influxdb is `1.8`, portainer `lts`), which the
baseline design pins first.

Rollback options:

1. Per unit, manual: set the previous pinned version in the config, re-render,
   restart. State on bind mounts is not rolled back by an image change; a
   database that migrated its data on upgrade may not start on the old image
   (INFERRED for Grafana, InfluxDB, Wazuh, OpenSearch). Take the state backup
   first (`scripts/backup-state.py`, VERIFIED to exist, covers n8n and Grafana
   state) and an OpenSearch snapshot (`scripts/10-snapshot-setup.sh`, VERIFIED).
2. Auto-update rollback exists: `podman auto-update --rollback` is on by default,
   reverts to the previous image if the restart fails, and detects failure more
   reliably when the container sends READY through sd-notify (VERIFIED, same
   page). That is a restart-success check, not a data check. Not relied on.
3. Whole variant back to Compose: `systemctl --user stop siem.target`, then
   `docker compose up -d` against the same bind mounts, provided ownership was
   not changed (podman.md section 7). Host changes (linger, subuid ranges,
   limits drop-in, sysctls) are not undone by stopping units; each is recorded
   with its undo.

Never run Docker and Podman on the same data at once (podman.md section 7).

## 8. Fit with secrets-sources and optional-components

secrets-sources.md defines one contract: secrets are environment variables of the
process that runs the command, filled from `doppler`, `envfile` or `credstore`.
Mapping for Quadlet:

- `envfile`: `siem.conf` holds names and secrets, mode 600, loaded by the
  launcher, not by `source`. Simplest for a first deploy.
- `credstore` (the one that fits this variant best, INFERRED): the unit declares
  `LoadCredential=` per secret (VERIFIED in secrets-sources.md, systemd.exec:
  readable by the unit's user, in `$CREDENTIALS_DIRECTORY`), and the launcher maps
  files to variables. A rootless user unit loading a root-owned credential file is
  not shown on a page read; INFERRED, test whether a user manager can read it.
  secrets-sources.md D3 says credstore ships later because "the Quadlet units come
  with the podman work": this design is that work, so credstore can follow it.
- `doppler`: the read-only service token file and `siem-run` pattern
  (VERIFIED scripts/live-deploy/siem-run) wrap `systemctl --user start`, but the
  values must reach the unit's environment, which `systemctl --user import-environment`
  or a render-time step would do. A secret on a systemd manager environment is
  visible to the account's processes (INFERRED). Open question Q3.
- Doppler and dev-before-production stays as secrets-sources.md section 5 says.

optional-components.md. Optional parts are units that are simply not installed:
the router add-on has no unit (n8n is out of scope here), each Grafana notifier
is a provisioning file (not a unit), `crowdsec` and `unifi-poller` live in an
`optional/` directory that the render step includes only when the config enables
them. The minimal profile is `siem.target` with Grafana, Prometheus,
Alertmanager (null receiver, optional-components.md Option A) and the data
services. One consequence for this variant: `GRAFANA_WEBHOOK_SECRET` becomes
optional in the grafana unit exactly when optional-components.md makes it
optional in compose.

## 9. Cockpit

VERIFIED (https://developers.redhat.com/articles/2026/04/13/managing-and-monitoring-podman-quadlet-red-hat-enterprise-linux-web-console,
2026-11-19): Quadlet containers appear in the Cockpit Podman page, support the
lifecycle operations through systemd, show health checks, and appear in the
Services, Metrics (CPU, memory, disk I/O) and Logs pages. Cockpit cannot create or
edit Quadlet files: they are written outside it, then `systemctl daemon-reload`
runs. Versions: improvements in cockpit-podman 100, 107, 108 and 116. The page
does not state whether rootless Quadlets are supported; a search summary says
cockpit-podman switches between user and system containers (INFERRED, second
source: not found on a vendor page). The first rehearsal must confirm that the
service account's units appear under a login that can see them. The account has no
login shell, so Cockpit access for it uses the administrator's own session with
the user-container view, or a Cockpit login for the service account (decision D7).
Reaching Cockpit itself is a network exposure (port 9090, INFERRED default) and
follows the same bind rules as the stack (a named variable, never open by default).

## 10. Test plan

What CI can test with no Podman host (all are new tests; nothing exists yet):

1. Render step, pure text: given a config file with placeholder values, the
   rendered units equal a golden set. Revert-proof by editing one golden line.
2. Lint every `.container` file as INI: required keys present (`Image=` fully
   qualified, `HealthCmd=`, `DropCapability=`, `NoNewPrivileges=`, `Memory=`),
   no literal secret, no `Environment=` secret name with a value, no
   `PublishPort=` without a bind variable. Same style as
   `tests/python/test_compose_security.py` (VERIFIED it enforces fail-closed
   secrets, loopback ports and opt-in Portainer on the compose file).
3. Parity: the set of container names, ports and bind variables in the rendered
   units equals the set in the compose file, so the two variants do not drift. A
   service added to compose without a unit fails CI.
4. Every `${NAME}` the units use is a name in the config file's documented list.
5. Where the runner has Podman (INFERRED: ubuntu-24.04 images ship it; verify
   the runner image first, per podman.md section 6), run the generator in dry run
   (VERIFIED `podman-system-generator --user --dryrun`) over the rendered files and
   `systemd-analyze --user --generators=true verify` (both VERIFIED on the unit
   page). That proves syntax and unit dependencies, not a start.
6. Registry egress allow-list: units use only registries already in the CI
   allow-list (VERIFIED .github/workflows/ci.yml lists them per podman.md).

Not testable without a host (a rehearsal host test, owner-run, listed not run):
reboot with no login and confirm all units active; `Notify=healthy` ordering;
memlock; ownership table; syslog source-address preservation; Cockpit shows the
units; rollback to Compose. The done-when of #112 is exactly this reboot test.

## 11. Host changes only the owner can make (listed, not done)

1. Create the service account; set subuid and subgid ranges; `loginctl
   enable-linger`.
2. Install Podman, netavark, aardvark-dns and cockpit-podman (an ai-hardening
   inspection record first, per policy).
3. Raise the account's memlock and nofile hard limits; keep `vm.max_map_count`
   from `scripts/02-bootstrap.sh`.
4. Decide on `net.ipv4.ip_unprivileged_port_start` or remap 514 and 443.
5. Place unit files under `/etc/containers/systemd/users/<uid>/`, then
   `systemctl --user daemon-reload`.
6. Firewall rules for the published ports. The Docker model does not carry over
   (podman.md section 3.6); `prometheus-otlp-firewall.sh` needs a rewrite and a
   Daybreak-tier review.
7. Data move and ownership with the original owners recorded.

## 12. Owner decisions (recommended answer first)

- D1. Quadlet files live under `/etc/containers/systemd/users/<uid>/`
  (admin-owned), not in the service account's home. Recommended yes.
- D2. One `.container` per service, no pods in the first release. Recommended yes.
- D3. Privileged ports: remap 514 and 443 through the existing variables first;
  lower the sysctl only if a sender cannot change port. Recommended remap.
- D4. OpenSearch memlock: set a user-manager hard limit for the account.
  Recommended yes; fall back to `memory_lock=false` only with your written OK.
- D5. cadvisor and Portainer are not carried to this variant; the restart-loop
  alert moves to a systemd based source or is dropped on Podman (podman.md Q7,
  Q8). Recommended drop Portainer, replace the alert.
- D6. No auto-update; manual pinned bumps after the seven-day hold. Recommended yes.
- D7. Cockpit access to the rootless units through the administrator's session.
  Recommended yes.
- D8. First release is the lowest-risk subset (Grafana, Prometheus, Alertmanager,
  exporters), then data tiers in the podman.md section 7 order. Recommended yes.
